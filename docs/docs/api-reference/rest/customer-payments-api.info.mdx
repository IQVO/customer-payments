Customer Payments moves money with the shipment facts: authorize at checkout, capture each shipment group's allocation when it ships (FulfillmentShipped), release on cancellation (FulfillmentCancelled), refund on lost or returned packages (PackageLost, PackageReturned), and re-authorize uncaptured allocations before the provider's authorization validity expires. This surface is called by checkout (authorize, void) and by storefront ops (refunds, reads); captures, releases and re-authorizations arrive as Kafka events or policies, never as REST writes. Errors are RFC 9457 problem details (application/problem+json) whose type is /problems/<slug>; shared types are not-found (404), illegal-transition (409), concurrent-update (409) and validation-failed (422), plus one kebab-case slug per Err of the model, and the idempotency problems idempotency-key-required and idempotency-key-invalid (400) and idempotency-key-reused (409). Every write (each POST) takes an Idempotency-Key header: a retry with the same key and the same request (method, path, body) replays the first answer (Idempotency-Replayed: true; any answer below 500 is stored for 24 hours, a 5xx is never stored), the same key with another request is 409 idempotency-key-reused. A body that is not one JSON object of the declared fields (unknown field, trailing data, over 64 KiB, a NUL character) is 400 malformed-request; a NUL character in a path is 404 resource-not-found. Not described under paths because the fleet REST ruleset (R1) rejects a custom-method suffix: the service also serves POST /refunds/{refundId}:retry (RetryRefund, ops only, Idempotency-Key required, no body), which moves a FAILED refund back to REQUESTED, tries the provider once more (at most 5 attempts) and answers 200 with the Refund; 404 not-found, 409 illegal-transition (not FAILED, or attempts used), concurrent-update or idempotency-key-reused, and the usual 400s. Any operation can answer 500 internal-error. The two collection reads are keyset-paged ({items, nextCursor}; invalid-limit, invalid-cursor and unknown-query-parameter are 400). No authentication."

REST contract of the customer-payments bounded context of the digital storefront, as the service serves it. Customer Payments moves money with the shipment facts: authorize at checkout, capture each shipment group's allocation when it ships (FulfillmentShipped), release on cancellation (FulfillmentCancelled), refund on lost or returned packages (PackageLost, PackageReturned), and re-authorize uncaptured allocations before the provider's authorization validity expires. The provider is reached through an ACL port (Authorize, Capture, Void, Refund, Reauthorize) with deterministic idempotency keys per (operation, authorizationId, groupNo); the storefront never sees a card number, only PSP tokens. This surface is called by checkout (authorize, void) and by storefront ops (refunds, reads); captures, releases and re-authorizations arrive as Kafka events or policies, never as REST writes. Errors are RFC 9457 problem details (application/problem+json) whose type is /problems/&lt;slug&gt;; shared types are not-found (404), illegal-transition (409), concurrent-update (409) and validation-failed (422), plus one kebab-case slug per Err of the model, and the idempotency problems idempotency-key-required and idempotency-key-invalid (400) and idempotency-key-reused (409). Every write (each POST) takes an Idempotency-Key header: a retry with the same key and the same request (method, path, body) replays the first answer (Idempotency-Replayed: true; any answer below 500 is stored for 24 hours, a 5xx is never stored), the same key with another request is 409 idempotency-key-reused. A body that is not one JSON object of the declared fields (unknown field, trailing data, over 64 KiB, a NUL character) is 400 malformed-request; a NUL character in a path is 404 resource-not-found. Not described under paths because the fleet REST ruleset (R1) rejects a custom-method suffix: the service also serves POST /refunds/\{refundId\}:retry (RetryRefund, ops only, Idempotency-Key required, no body), which moves a FAILED refund back to REQUESTED, tries the provider once more (at most 5 attempts) and answers 200 with the Refund; 404 not-found, 409 illegal-transition (not FAILED, or attempts used), concurrent-update or idempotency-key-reused, and the usual 400s. Any operation can answer 500 internal-error. The two collection reads are keyset-paged (\{items, nextCursor\}; invalid-limit, invalid-cursor and unknown-query-parameter are 400). No authentication.
